## 2. 預約管理（唯讀部分先做）

- [ ] 預設顯示「今天起的所有預約」，依日期由近到遠
- [ ] 狀態篩選切到 **預約成立／已取消／已拒絕** 各一次，清單都能正常載入（**不跳索引錯誤**）
- [ ] 「重新整理」按鈕有作用

接著是會改資料的部分。**建議先用住戶端自己開一筆測試預約**，拿它來測，不要動真住戶的單子：

- [ ] 對測試預約按 **取消** → 跳確認框 → 確認後狀態變「已取消」
- [ ] 回住戶端看，該時段**重新開放**可預約
- [ ] 該住戶的單日/單週次數有被退回（可再訂一次同場地驗證）

## 3. 場地與時段設定（會影響住戶端）

先測不破壞的：

- [ ] 六個場地都列出來，各自顯示代號、名稱、容納人數、順序、簡介
- [ ] 每個場地下方都列出 **7 個時段**（08:00 起每 2 小時）
- [ ] 改某場地的**簡介**文字 → 按「儲存場地設定」→ 出現綠色「已儲存」
- [ ] 回住戶端首頁，場地卡片的簡介**同步更新**（若沒變，強制重新整理一次）

再測開關類（記得測完改回來）：

- [ ] 把某場地改成 **暫停開放** → 儲存 → 住戶端該場地無法預約
- [ ] 改回 **開放** → 住戶端恢復
- [ ] 把某場地改成 **需物業審核** → 用住戶端訂一筆 → 狀態應是「待審核」而非「預約成立」
- [ ] 回第 2 節測核准與拒絕，測完把場地改回 **自動確認**
- [ ] 把 **同帳號單日上限** 設成 1 → 同一天同場地訂第二筆應被擋下 → 測完改回原值

最後才測新增與刪除：

- [ ] 按「＋ 新增場地」，代號填 `test-room`，名稱填「測試室」
- [ ] 新場地自動帶入 **7 個時段**，且住戶端首頁看得到它
- [ ] 在測試室新增一個時段（例如 22:00–23:00，只勾週六）→ 出現在時段表
- [ ] 刪除剛才那個時段 → 跳確認框 → 確實消失
- [ ] **刪除「測試室」** → 要按**兩次**確認 → 場地與其時段設備一併消失

> ⚠️ 新增時段的文件代號是用**開始時間**產生的（`t0800`、`t1000`…）。這代表若新增一個
> 開始時間與現有時段相同的段（例如已有 08:00–10:00，又加一個 08:00–12:00），
> **舊的會被直接覆蓋、不會有任何警告**。測的時候避開已存在的開始時間。

**復原**：務必確認「測試室」已刪除、被你改動的場地都改回原設定。

### 讀程式碼時發現、但還沒動的兩處

1. **今日總覽的使用率分母寫死 7**（`admin.js` `loadDashboard()`）
   `usage = active.length / (facs.length * 7)`。一旦有場地時段數不是 7，百分比就失真。
   建議改成加總各場地實際的時段數。
2. **新增時段會靜默覆蓋同開始時間的舊時段**（`admin.js` `addSlot()`）
   文件代號是 `t{HHMM}`，`setDoc` 不會擋既有文件。建議新增前先檢查是否已存在並提示。

兩項都不影響目前運作，要不要修由你決定。
